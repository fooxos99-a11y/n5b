# توحيد بداية تشغيل التطبيق الأصلي

حالة الإصدار،17 أكتوبر2026: رُفعت تعديلات التطبيق الأصلي بالإصدار1.0.19 (24)، وأصبح متاحًا في TestFlight بحالة `Testing`. أُرسل البناء نفسه إلى App Store وأصبح `Waiting for Review` بدل البناء23. لم تعتمد Apple الإصدار بعد. الموقع وتحويل Expo خارج هذا الرفع.

تعديل محلي لاحق لرفع البناء24: أزيلت روابط الشروط والخصوصية والدعم وطلب حذف الحساب وزر قائمتها من صفحة الدخول بالكامل، وصفحة التسجيل خالية منها أيضًا. توجد الروابط بعد الدخول تحت «المساعدة والخصوصية» داخل قائمة حساب الطالب أو الشريط الجانبي المشترك، مع بقاء روابط إعدادات الإدارة. حُدّث وصف مسار الوصول في النصوص القانونية فقط، دون تغيير سياسة الحذف. اجتازت المعاينة الفعلية للجوال والكمبيوتر بالنمطين، وفتح نافذة طلب الحذف وإلغاؤها دون إرسال طلب، وLint و30 اختبارًا مرتبطًا وبناء الجوال. الشواهد الحالية في `outputs/legal-account-only-20261017/validation.json` وتحل محل معاينة القائمة أسفل الدخول السابقة. هذا التعديل غير موجود في البناء24 ولم يُرفع أو يُنشر.

## تعديل محلي: سريان البرنامج الأسبوعي —17 أكتوبر2026

- أُصلح تعارض أيام الإعدادات مع أيام الأسبوع المثبّتة عند تسجيل أول درجة؛ أصبح للبرنامج خيار «من اليوم» أو «من الأسبوع القادم» (الافتراضي). تحفظ السياسة داخل الأسبوع بحسب التاريخ، ولا يعاد احتساب الأيام الماضية أو استبدال درجاتها. تبقى الأجزاء التي بدأ تسجيلها اليوم ثابتة، مع فصل قفل القراءة الذاتية عن الحضور والتسميع حتى لا تمنع قراءةٌ مسجلةٌ تفعيلَ السبت.
- عند تطبيق التعديل من اليوم، تظهر مقادير الحفظ والربط والمراجعة من الخطة النشطة عند إعادة فتح التسميع، بحسب محفوظ الطالب. تتبع مواعيد الخطة والتعويض والتقارير السياسة السارية لكل تاريخ. لا تنشأ مهام في الإجازات أو أثناء إيقاف الخطة، ولا تتكرر عند فتح الجلسة مجددًا. تظهر أسباب غياب الخطة أو إيقافها في الجلسة.
- تُحفظ درجات الأسبوع في حد100 بخفض الهامش ثم الأوزان اليومية غير المسجلة بالتناسب، مع حماية الأوزان السابقة وجلسات الأسبوع. الحفظ معاملة واحدة ويرفض تعديلات الجلسات القديمة المتعارضة. طلبات الإصدارات القديمة التي لا تحتوي موعد السريان تبقى مدعومة وتؤجل التعديل للأسبوع القادم.
- اجتازت `npm run verify`: الامتثال وLint و807 اختبارات وتدقيق الاعتماديات بصفر ثغرات وبناء الويب. اجتاز `npm run build:mobile` أيضًا. الفحص الفعلي على Chromium محلي موصول بـAPI وMySQL3321 معزولين، دون محاكاة استجابات API:10 حالات تكامل و3 حالات لحفظ الدرجات والسياسة والصلاحيات، و8 حالات لواجهتي المدير والمشرف على390 و1440 بالنهاري والليلي، وفتح مصحف التسميع في المقاسات والنمطين.
- حالة السبت اختُبرت بساعة اختبار ثابتة17 أكتوبر الساعة12 ظهرًا بتوقيت الرياض، ثم أُعيد API إلى الساعة الحقيقية وتحقق الحفظ والتوافق مع العملاء القدامى. الشواهد في [تقرير البرنامج الأسبوعي](../outputs/weekly-schedule-20261017/report.html)، ومنها صور الواجهات وسجلات التحقق وحماية التغييرات السابقة. لا يثبت ذلك تجربة iPhone فعلي.
- نُفذت بيانات الاختبار محليًا بعد نسخة احتياطية، دون تغيير مخطط قاعدة البيانات. لم تتغير ملفات المصحف أو سياسة تنفيذ القرآن عند المشرف أو Expo. التعديل غير منشور، ولم يحدث commit أو push. يحتاج تشغيله على الحسابات المستضافة نشر تحديث API إلى جانب حزمة التطبيق؛ لم يشمل هذا العمل تصريحًا بنشر API أو الموقع.

## السلوك

- أزيل مؤشر شاشة التشغيل الأصلية في iOS، وطابقت بداية Android اللون الأخضر نفسه دون الحلقة السابقة. تبقى شاشة النظام الثابتة القصيرة قبل تشغيل الواجهة، ولا تُوصف بأنها أنيميشن أصلي.
- صارت واجهة HTML المبكرة مالكة أنيميشن الشعار والزخرفة الموجودين، دون انتظار React. أزيلت نسخة React المكررة ونافذة التجربة القديمة، وأصبحت الاختبارات تستخدم المدخل الحقيقي.
- ينضم React إلى الخط الزمني الجاري، ويحمّل المسار وبياناته خلف الغطاء نفسه. يظهر الشعار ثابتًا إذا انتهت الحركة قبل اكتمال التجهيز، ثم تتلاشى الواجهة مرة واحدة. لا يعاد الأنيميشن عند التنقل أو إعادة التركيز داخل الوثيقة نفسها.
- بعد15 ثانية من تعثر البداية يظهر نص واضح وإعادة المحاولة، حتى إذا لم يصل ملف React. فشل الشعار يعاد بطلب جديد لتجاوز احتفاظ WebKit بالصورة الفاشلة، دون إعادة تحميل التطبيق الجاهز. تعطل React يكشف نافذة الخطأ المعتمدة ولا يحبسها خلف الغطاء.
- روعيت حركة النظام المخفضة، وRTL، وتعطيل التفاعل خلف البداية، واستعادة لوحة المفاتيح، وتقديم خط Cairo مبكرًا من تعريف الخط المشترك. أضيف متحكم البداية والشعار الأبيض إلى التخزين الأولي للويب. بقي تحميل الإجراءات اللاحقة بالمؤشر المشترك المعتمد.
- لم يتغير المصحف أو ألوان الصفحات أو صلاحيات الحسابات أو سياسة تنفيذ القرآن عند المشرف، ولم تدخل ملفات Expo في الإصلاح.

## التحقق

- نجح `npm run verify` الحالي على مساحة التطبيق الأصلي المعزولة: الامتثال وLint و784 اختبارًا وتدقيق الاعتماديات بصفر ثغرات وبناء الويب. لا ينسب التدقيق النظيف إلى مساحة تحويل Expo المختلطة أو عوائقها السابقة.
- نجح `npm run build:mobile`، ثم مزامنة iOS وAndroid وبناء APK Android Debug. طابقت بداية التشغيل داخل APK المصدر الحالي وملفات iOS المزامنة حرفيًا. كانت معالجة مسارات Gradle والاعتماد الموجود محلية فقط دون تغيير إصدار اعتماد أو lockfile أو إعداد نشر.
- اجتازت26 حالة في Chromium وWebKit:320 و390 و1440 والاتجاه الأفقي، تأخير JavaScript والبيانات، احتفاظ عنصر الأنيميشن بهويته، فشل الحزمة والشعار وإعادة المحاولة، تعطل React، تقليل الحركة، واستعادة حسابات المدير والطالب والمشرف. شمل الدخول401 ثم النجاح، غياب الحساب بعد الرفض، وعدم تكرار طلب الدخول أو إعادة الأنيميشن.
- اجتازت3 حالات استمرار مؤشر التحميل عند تبدل مراحل لاحقة، و3 حالات استعادة الحساب والإحصائيات بعد تعطل التخزين المحلي وفشل الشبكة ثم عودتها. مجموع حالات المتصفح32. كانت الطلبات وبيانات الدخول معزولة عن الإنتاج.
- واجه التشغيل الأول لفحص إعادة الاتصال مهلة reload أثناء البناء المتزامن؛ اجتاز تشغيله المنفرد لاحقًا المقاسات الثلاثة. بقية إخفاقات التطوير ومعالجتها موثقة في ملخص التحقق، ولم تُعطل قواعد لتجاوزها.
- اكتمل بناء Xcode الموقّع والأرشفة والتصدير والرفع من GitHub Actions. طابقت الحزمة متحكم البداية والمصدر، وثبت غياب مؤشر التحميل من شاشة iOS المترجمة، وتطابق2420 ملف مصحف مع مصدر الإصدار، بما فيها604 خطوط و604 تخطيطات صفحات. لم يحدث تشغيل على iPhone أو Android فعلي؛ المتصفح والمحاكي والبناء لا يثبتان تجربة هذه الأجهزة.
