# لوب الجودة

تُقرأ هذه التعليمات فقط عند طلب Loop صراحة، مع قواعد AGENTS.md الأساسية.

### التفعيل والنطاق

- لا يعمل اللوب في المهام العادية؛ يُفعّل فقط عند قول المستخدم: «شغّل لوب الجودة» أو طلب Loop صراحة.
- يحدد المستخدم النطاق: صفحة، ميزة، تطبيق الويب، تطبيق الجوال، أو المشروع كاملًا. لا توسّع النطاق من تلقاء نفسك.
- عند طلب المشروع كاملًا، أنشئ قائمة بالصفحات والمسارات والمنصات قبل البدء، ثم واصل تباعًا دون انتظار أمر لكل صفحة.
- لا تطلب موافقة بين الدورات للتعديلات المحلية القابلة للتراجع. اطلبها فقط عند قرار جوهري أو نشر أو حذف أو عملية مدمرة أو وصول خارجي جديد.

### دورة العمل

1. شغّل TestSprite على النطاق إذا كان متصلًا ومهيأً، وإلا استخدم E2E أو المتصفح والفحوص المحلية واذكر البديل.
2. سجل دليلًا قابلًا لإعادة الإنتاج: المسار، المقاس، الخطوات، النتيجة الحالية والمتوقعة.
3. أصلح أعلى مشكلة مؤكدة بأقل تغيير ودون لمس ملفات غير مرتبطة.
4. أعد الاختبار الفاشل نفسه أولًا.
5. شغّل الاختبارات المستهدفة و`npm run verify:quick` بعد كل مجموعة إصلاحات مترابطة.
6. سجل الصفحة والمشكلة والإصلاح والنتيجة، ثم انتقل تلقائيًا للدورة التالية.
7. قبل اكتمال النطاق شغّل `npm run verify` وطبّق بوابة الامتثال.

### معايير الواجهة والتوقف

- اختبر على الأقل: هاتف `360px`، جهاز لوحي `768px`، وسطح مكتب `1440px`.
- افحص RTL، و`var(--font-ui)`، واللمس، والقص والتمرير الأفقي، وحالات التحميل والفراغ والخطأ، والتنقل بلوحة المفاتيح.
- لا تعتبر الواجهة سليمة بصريًا دون فحص فعلي أو لقطة شاشة أو دليل DOM/CSS.
- TestSprite طبقة E2E إضافية ولا يستبدل الاختبارات الحالية.
- الحد الأقصى ثلاث محاولات للمشكلة الواحدة، وتوقف إذا تكرر الفشل نفسه مرتين بعد إصلاحين مختلفين.
- لا نشر، ولا SQL إنتاجي، ولا commit أو push ضمن اللوب إلا بطلب صريح مستقل.
