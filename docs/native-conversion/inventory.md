# حصر تحويل نخب — W00-01 وW00-02

فحص المصدر الحالي بتاريخ 2026-10-14. الحصر يتبع ملفات العمل الحالية، بما فيها تعديلات المصحف غير المثبتة. هو حصر للمسارات والعمليات؛ لا يثبت تشغيل تطبيق نيتف أو نجاح API على أجهزة.

النتيجة: **41 سطحًا وظيفيًا** (منها مجموعة إعدادات بثماني صفحات)، **153 مرجع عملية خدمة** منها عملية صف قديمة موثقة، و**157 تعريف طلب**، إضافة إلى 7 طلبات مباشرة مشتركة. الملفات والتبويبات والروابط البديلة ليست شاشات مستقلة في هذا العدد.

المرجع التفصيلي الآلي هو [inventory.json](inventory.json). يحتوي مصادر كل عملية واستعمالاتها وطلبات الخادم المرتبطة ونسخة بصمات الملفات. لا توجد بيانات حسابات أو أسرار في الحصر.

## حدود الحسابات والمداخل

- مدخل الطالب الفعلي هو StudentHome في /. يعيد App روابط الطالب /portal إلى /. فروع الطالب القديمة وStudentPlanPanel ليست شاشات طالب فعالة في إعداد المنتج الحالي.
- المشرف والإداري صاحبا منح الإدارة يستعملان /dashboard؛ والمشرف بلا تلك المنح يستعمل /portal. الإداري بلا منح يصل إلى حالة عدم توفر الأقسام الحالية.
- المصحف والتسميع في لوحة الإدارة خاصان بالمشرف؛ المدير لا تظهر له صفحة مصحف.
- تتحكم مفاتيح الميزات وسياسة التحضير في ظهور الشاشات وقت التشغيل؛ الحصر يسجل ما يمكن إتاحته وفق الإعدادات، ولا يعد بإتاحة كل الوظائف لكل حساب.
- أرقام planSteps تربط كل عملية بنطاق التحويل المناسب. معيار القبول التفصيلي يبقى في الخطة الرئيسية، وقد ترتبط قراءة مشتركة بأكثر من خطوة.
- screenIds في عمليات API تربط تبعيات المصدر المشترك والمزامنة والفروع المشروطة، وليست مصفوفة صلاحيات. قد تذكر خدمة حفظ محلي عدة أدوار بينما تطلب الشاشة بيانات حسابها فقط.
- جذور الشاشة تشمل hooks التي تقدم بيانات من الغلاف؛ وتُحصر المكونات المفوضة المشتركة كوظيفة واحدة مع ربطها بالشاشات التي تستعملها.
