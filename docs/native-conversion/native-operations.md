# نقل التسجيل ووظائف الحسابات إلى نخب النيتف

هذا الجزء ينقل رحلة مراجعة طلب التسجيل وإنشاء حساب الطالب، وإدارة الطلاب والمجمعات والحلقات، ومساحة الطالب، ووظائف أولية للمشرف والإداري. التنفيذ داخل `mobile/` ويستخدم خادم نخب وعقوده الحالية؛ لم نعد كتابة الموقع أو نغير سياسة التقييم أو نفتح عمليات جديدة للطالب.

## القواعد التي حافظنا عليها

- اختبار المحفوظ يجب أن يحتوي نتيجة لكل مقدار قبل القبول النهائي. النتيجة «راسب» لا تمنع إنشاء الحساب بعد اكتمال الاختبار؛ يضاف المحفوظ المجتاز فقط، كما يفعل الخادم الحالي.
- القبول المبدئي والقبول النهائي ونتيجة التواصل حالات منفصلة. فشل رسالة التواصل لا يتحول إلى ادعاء أن حساب الطالب لم ينشأ؛ وعدم وجود تأكيد إرسال يظهر بوضوح.
- تعديل الطالب يطلب كلمة المرور، ويحدث بيانات الدخول وينهي جلساته الحالية، وفق `PUT /students/:id` الحالي. الحقل لا يستخرج كلمة المرور القديمة أو يعرضها.
- تعديل الدرجات يرسل مقدار الإضافة أو الخصم والسبب. لا يرسل الرصيد النهائي، ولا يسمح بخصم يتجاوز الرصيد. الأرقام العربية والفارسية والفاصل العشري العربي تتحول قبل التحقق دون تغيير كلمة المرور.
- حذف الحلقة يبقي الطلاب بلا حلقة. حذف الطالب يؤكد أن الحساب وسجلاته المرتبطة ستُحذف.
- تنفيذ مهام القرآن من حساب الطالب غير متاح حاليًا. [السياسة المشتركة](../../shared/quran-execution-policy.js) تجعل التنفيذ عند المشرف، والخادم يرفض محاولة الطالب بـ`409`؛ لذلك لم نضع أزرار إنجاز تخالف القاعدة.
- اكتمال التسميع يُعرض من `recitationFinished` الذي يعيده الخادم، حتى إن لم تبق مهام اليوم. لا نحوله إلى درجة أو ادعاء اجتياز.
- الموقع يُطلب عند ضغط تحضير المشرف وحين تشترطه سياسة الجهة. نستخدم إذن الموقع أثناء الاستخدام، ونوقف القراءة بعد أخذ إحداثيات واحدة أو انتهاء المهلة. قرار قبول النطاق والتوقيت والهوية يبقى عند الخادم.

## حماية الحساب والحفظ

الخدمات مرتبطة بهوية الحساب ودوره وجهته، وتفحصها قبل الطلب وبعده. خدمة قديمة لا تستطيع الاستمرار بعد الخروج أو تبديل الحساب أو الجهة. المنح تأتي من الجلسة الحالية والخادم، ولا تعتمد على بيانات رابط أو دور يرسله المستخدم.

عند فقد الاستجابة بعد عملية حفظ، قد يكون الخادم نفّذها. [حارس الحفظ](../../mobile/src/hooks/useVerifiedMutation.ts) يوقف إعادة العملية حتى ينجح تحديث البيانات؛ فشل التحديث يبقي النافذة والحالة غير المؤكدة. [إدارة التسجيل](../../mobile/src/screens/RegistrationManagementScreen.tsx) تمنع العمليات أيضًا عند فشل تحديث قائمتها. توجد حواجز متزامنة للضغط المكرر، وإلغاء للطلبات المتأخرة عند تغير السياق.

الحقول والأزرار والنوافذ والاختيارات والتأكيدات ومناطق التحميل والخطأ مكونات مشتركة مستقلة داخل [components](../../mobile/src/components/ScreenLayout.tsx). الواجهات تدعم RTL والثيمين وتلتف على مقاسات الجوال؛ التحقق البصري الفعلي موضح في سجل التحقق أدناه.

فحوص HTTP استخدمت ثلاث قواعد بيانات محلية جديدة ومعزولة: جهة الاختبار، منصة الاختبار، وجهة ثانية. بيانات اتصال المستلمين الاصطناعية فارغة، وحاجز طلبات الشبكة في اختبار العقود يسمح بعناوين loopback فقط؛ لم تُرسل رسائل خارجية. القالب الفارغ قد يعود إلى القيمة الافتراضية عند تطبيع إعدادات الخادم، ولذلك لا نعتمده وسيلة تعطيل للإرسال. سجل النتائج لا يحتوي كلمات المرور أو التوكنز؛ أغلقت اتصالات الخادم وقواعد البيانات، وبقيت قواعد الاختبار محفوظة للمراجعة.

اختبار المتصفح استخدم مسارات الخادم الحقيقية للحفظ والقراءة. حقن فشل الاتصال اقتصر على حالة مستقلة: أُرسل تعديل الدرجات إلى الخادم وحُفظ في SQL ثم فُقدت الاستجابة، وفشل تحديث البيانات مرة قبل نجاحه. بقيت العملية موقوفة حتى التحقق، ولم يتكرر التعديل. فحص31 حالة نافذة أثبت انتهاء الحركة وشفافية1 وخلفية معتمة قبل التقاط الصور؛ صور المعاينة لا تثبت أنيميشن الجهاز.

صور ممثلة: [اختبار القبول في الثيم الداكن](../../mobile/evidence/operations-ui/admission-assessment-320-dark.png)، [تعديل الطالب على جوال320](../../mobile/evidence/operations-ui/student-edit-320-light.png)، [نتائج الطالب على سطح المكتب](../../mobile/evidence/operations-ui/student-results-1440-light.png)، [طلاب المشرف](../../mobile/evidence/operations-ui/supervisor-roster-390-dark.png). سجل المتصفح يؤكد إغلاق الخادم والمتصفح دون فشل تنظيف.

بصمة APK: `90AB1946D3F1F35EDB237B24DA11D1237B8F7EB2A6118CAD2655EABCC92A4D3A`، وحجمه93,425,653 بايت. يحتوي وحدتي `expo-location` و`expo-clipboard` المتوافقتين مع Expo57. هو development client يحتاج Metro للمصدر الحالي، ولا يحتوي حزمة JavaScript مضمّنة. بصمات مرحلة البناء تصف النسخة المنسوخة وقت البناء؛ تحقق المصدر الجاري على الواجهة والمحاكي له سجل مستقل.

على محاكي نخب المملوك`emulator-5584`، اكتملت رحلة التسجيل والقبول ودخول الطالب، وعمليات الطلاب والحلقات، وتحضير الطالب من المشرف، واستعادة حسابات الطالب والمشرف والإداري من SecureStore بعد إيقاف العملية. رفض إذن الموقع لم ينشئ طلب تحضير أو صفSQL. عند السماح أثناء الاستخدام، أُرسلت إحداثيات اصطناعية عبر`adb emu geo fix`؛ حفظ الخادم تحضير المشرف بمسافة0 متر ضمن سياسة150 مترًا. هذا دليل إذنAndroid ومحاكيه، وليسGPS هاتف فعلي. صور ممثلة: [خطة الطالب](../../outputs/native-conversion/android-operations/c23058f9-student-home.png)، [تحضير المشرف](../../outputs/native-conversion/android-operations/c23058f9-supervisor-gps-attendance.png)، [طلاب الإداري](../../outputs/native-conversion/android-operations/c23058f9-admin-students.png).

حُفظت المحاولات السابقة الفاشلة في سجل المحاكي. الاسم الاصطناعي`OpsTemporaryCircle` أرسل حرفR مرتين بسرعة بلوحة مفاتيحADB، ففعّل اختصار إعادة تحميل نسخة التطوير؛ استُبدل باسم لا يفعل ذلك، دون تغيير سلوك التطبيق. فحص نجاح حضور الطالب احتاج الوصول إلى الرسالة الواقعة أعلى منطقة التمرير. اكتملت الرحلة النهائية والتنظيف: انتهت عملياتAPI وMetro والمحاكي، وأزيلت تحويلات المنافذ وأُبطلت الجلسات الاصطناعية، دون مساس بمحاكي المشروع الآخر. أوقفنا MySQL المحلي الذي أنشأناه إيقافًا سليمًا مع الاحتفاظ بقواعد الاختبار؛ [تقرير الملكية والإغلاق](../../outputs/native-conversion/native-operations-mysql-runtime.json) يثبت تحرير3310.

## حدود هذا الجزء والخطوات التالية

التحويل الكامل ما زال مفتوحًا. لم تُنقل بعد بقية أقسام الإدارة، وإدارة المشرفين والإداريين، وإنشاء وتعديل الخطط من واجهة الإدارة، والتقييم بالمصحف والمسودات والتعويض، والمكالمات والإشعارات، وترحيل Capacitor والمزامنة، وبقية وظائف المتجر والتقارير.

شرط «تحضير المشرف قبل العمل» المكتوب فيW08-02 لا يطبقه الموقع الحالي: [زر إلغاء تنبيه التحضير](../../src/components/attendance/StaffAttendancePrompt.jsx) يسمح بإغلاقه، و[بوابة المشرف](../../src/pages/AccountPortal.jsx) تتيح التسميع وسجله دون اشتراط التحضير. نقلنا السياسة الموجودة، وأبقينا الخطوة مفتوحة لحسم هذا الشرط؛ لم نغير معيارها أو نضف منعًا جديدًا.

الترتيب لم يُنقل مع بطاقة النقاط، وربط المشرفين بالحلقات لم يُنقل مع إدارة الحلقات. وضع النتائج والحضور والجلسات المعروضة لا يعني اكتمال حفظ تقييم التسميع أو حساب المشرف كله.

عرض عدد التكرارات المطلوب والمنفذ في مساحة المشرف يحتاج نقل حقوله والتحقق منه؛ ظهور نوع المهمة لا يثبت اكتمال هذا الجزء.

لا يوجد دليل جهاز Android فعلي أو iPhone فعلي، ولم يُبنَ iOS native لأن المضيف Windows. Hermes لا يثبت تشغيل iPhone. لم يحدث نشر أو SQL إنتاجي أو commit أو push، ولم نمس تعديلات المصحف الجارية للمستخدم.

تعرض [الخطة الرئيسية](../native-conversion-plan.md) حالة كل خطوة، ولا تتحول الخطوة إلى`done` إلا بعد دليل معيارها كاملًا.
