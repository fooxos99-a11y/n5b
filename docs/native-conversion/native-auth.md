# الدخول وطلب التسجيل في تطبيق نخب

بدأ نقل رحلة الدخول والتسجيل إلى مكونات React Native. التطبيق العادي يفتح شاشة الدخول بعد البداية، وتبقى تجربة المصحف والتخزين والمكالمة مسار فحص مستقلًا عند ضبط `EXPO_PUBLIC_NATIVE_PROBES=1`.

## التنفيذ

- حقل رقم الدخول يستخدم قاعدة الأرقام العربية والفارسية والإنجليزية الموجودة في الموقع، ويحفظ الرقم كنص. كلمة المرور تبقى كما أُدخلت؛ الخادم يقرر قبول الحسابات التي لا تملك تجزئة كلمة مرور وفق سلوكها الحالي.
- حقول مشتركة بعناوين ثابتة وتركيز واضح، وإظهار كلمة المرور وإخفائها، والتنقل بين الحقول وإرسال لوحة المفاتيح. قفل متزامن وحالة تحميل يمنعان إرسال الدخول مرتين.
- عميل API مستقل ومكتوب الأنواع، بعنوان صريح. الطلبات المحمية تحمل Bearer وسياق الجهة؛ الطلبات العامة لا تحمل جلسة. تُرفض الوجهات الخارجية غير الآمنة وتحويلات الطلب، ولا يُعرض نص خطأ داخلي خام.
- SecureStore يحفظ اعتماد الجلسة على Android وiOS. الاستعادة تستدعي `GET /api/auth/session`؛ لا يُعرض حساب بناءً على معلومات محلية وحدها. المسار يعيد الاسم الحالي والدور والمنح وسياق الجهة دون رمز الجلسة أو تجزئتها، ويرفض الموظف المعطل أو تغير دوره.
- الخروج يمسح الحالة المحلية ويلغي الطلبات، ويحاول إبطال الجلسة في سياقها القديم. فشل الإبطال على الخادم يُذكر صراحة. لا تمس نتيجة متأخرة لحساب سابق الحساب الجديد، ويُحجب الحساب عند تعذر التحقق من الجلسة.
- صفحات الدخول للأدوار الأربعة تعرض الهوية والمنح المتحقق منها فقط. **وظائف المدير والطالب والمشرف والإداري ما زالت قيد النقل؛ هذه الصفحات ليست إغلاقًا لمراحل الحسابات.**
- طلب التسجيل يحمل معرّف الجهة الحالي، ويعرض الإغلاق والتحميل وأخطاء الاتصال. ينقل الاسم والجوال والهوية والعمر والمجمع والحلقة ونطاقات الأجزاء؛ تغيير المجمع يمسح الحلقة السابقة. يعاد استخدام قواعد دمج المحفوظ وتوسيعه من الموقع.
- إرسال التسجيل ينشئ طلبًا للإدارة. لا ينشئ جلسة أو حساب طالب قبل القبول النهائي. تُعرض أخطاء الإغلاق والتكرار وحد المحاولات برسائل محددة وآمنة.
- الروابط تقبل صيغة التسجيل الحالية أو `nukhab://register?registrationNumber=...` مع معرّف جهة صالح. الرابط لا يمنح دورًا ولا يغيّر عنوان الخدمة.

## التشغيل المحلي

من `mobile/` اضبط `EXPO_PUBLIC_API_BASE_URL` إلى عنوان API المتحقق منه. HTTPS مطلوب للوجهات الخارجية؛ HTTP متاح لعناوين الاختبار المحلية فقط. يمكن ضبط `EXPO_PUBLIC_REGISTRATION_NUMBER` إلى معرّف جهة متحقق منه لإظهار مدخل التسجيل عندما يؤكد الخادم أنه مفتوح. لا توجد قيمة إنتاجية افتراضية مخمّنة.

معاينة المتصفح تحتفظ بالاعتماد في ذاكرة المتحكم فقط، ولا تستخدم localStorage أو sessionStorage لحفظه. إعادة تحميل المتصفح تتطلب الدخول مجددًا؛ هذا يختلف عن استعادة SecureStore على الجهاز.

```powershell
# تحقق HTTP والخادم، من جذر المشروع
node --loader ./tests/fixtures/isolated-server-loader.mjs tests/nativeConversionContracts.mysql.mjs
node --loader ./tests/fixtures/isolated-server-loader.mjs tests/nativeAuthUi.browser.mjs

# تحقق الجوال، من mobile
npm run verify:quick
npm run audit
npm run test:web
```

## الأدلة والحدود

نتائج هذه الدفعة محفوظة في [تقرير التحقق](../../mobile/evidence/auth-validation.json)، و[اختبار الواجهات](../../mobile/evidence/auth-ui.json)، و[عقود HTTP](evidence/api-contracts.json). تنفذ اختبارات HTTP والواجهات داخل قواعد MySQL محلية جديدة، ببيانات اصطناعية وكلمات مرور مولدة لا تصدر في التقارير. لا تستعمل الخادم الخارجي أو بيانات التشغيل.

فحص المتصفح يثبت مكونات الواجهة والربط الفعلي بـHTTP المحلي؛ لا يثبت لوحة مفاتيح iPhone أو Keychain أو حركة الجهاز. تصدير Hermes يثبت تجميع JavaScript للمنصتين، وليس بناء IPA أو تشغيل هاتف فعلي. يبقى audit الخاص بالجوال غير مجتاز بسبب الاعتماد المعروف في أدوات Expo؛ لم تُعطّل بوابة التحقق.

حُدث allowlist في helper بناء Windows ليضم ملفات الأرقام والأجزاء ومعرّف الجهة والمنح المشتركة اللازمة للشاشات الجديدة فقط. اجتاز تحليل PowerShell وفحص الاعتماديات؛ لم يُجرَ بناء Android جديد لهذه الإضافة، وتبقى نتيجة APK السابقة سجلًا مستقلًا.

الروابط والصلاحيات والتسجيل والإغلاق في [ملف الخطوات](../native-conversion-plan.md) تحدّث بحسب الأدلة الفعلية. لم يُنفذ نشر أو SQL إنتاجي أو commit أو push.
