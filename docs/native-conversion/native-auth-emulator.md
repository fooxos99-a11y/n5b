# الدخول والجلسة على محاكي Android

نجح فحص المصادقة الفعلي المحلي في 14 أكتوبر 2026: **16 تحققًا و8 صور** من تطبيق Android المتصل بخادم Express وقواعد MySQL مستقلة. وبعد تحسين تباين شعار الدخول في الوضع الداكن، اجتازت الشيفرة الحالية **7 تحققات إضافية و4 صور** للشاشة الفاتحة والداكنة ودخول المدير والخروج الآمن. لم تُستخدم استجابات وهمية للمسارات الرئيسية. التفاصيل وبصمات المصدر والصور في [native-auth-emulator.json](evidence/native-auth-emulator.json)، وأداة إعادة الفحص في [nativeAuthEmulator.mjs](../../tests/nativeAuthEmulator.mjs).

السجل يحفظ تشغيل المصادقة الكامل تحت `historicalFullRun` بمصدره الأصلي. بصمة `LoginScreen.tsx` فيه تبدأ بـ`C145013E`، وبصمة النسخة الحالية تبدأ بـ`996CD482`. بقية ملفات المصادقة والتحكم مطابقة؛ التغيير اللاحق اختار الشعار الأبيض الموجود للوضع الداكن فقط. فُحصت [الشاشة الفاتحة الحالية](../../outputs/native-conversion/android-auth/current-login-light.png) و[الشاشة الداكنة الحالية](../../outputs/native-conversion/android-auth/current-login-dark.png) بصريًا، وظهر الشعار بوضوح في الحالتين. لا يُنسب التشغيل التاريخي إلى بصمة شاشة أحدث.

## نطاق الدليل

البيئة محاكي Android 15 / API 35 / Google APIs / x86_64، وليست جهازًا فعليًا أو iPhone. أُعيد استعمال AVD المملوك `Nukhab_Native_8536dec45d55` على `emulator-5584`، ومساره `C:\Users\RAIQ\.android\avd\Nukhab_Native_8536dec45d55.avd`. بقي `emulator-5560` خارج النطاق.

استُعمل APK debug المثبت سابقًا، دون تثبيت بديل أو مسح التطبيق. طابقت بصمته دليل البناء السابق. شُغل مصدر JS الحالي من Metro خاص مع `EXPO_PUBLIC_NATIVE_PROBES=0` وعنوان API محلي صريح؛ هذه نسخة development client ولم تُنشأ نسخة release أو عملية نشر.

## العزل وحماية الأسرار

استعمل تشغيل المصادقة الكامل ثلاث قواعد محلية جديدة فقط:

- `nukhab_native_android_4279fcd6b7774cab` لجهة `native-android-fixture`.
- `nukhab_native_android_4279fcd6b7774cab_platform` لربط الجهة بقاعدة الاختبار.
- `nukhab_native_android_4279fcd6b7774cab_other` لجهة التحقق الثانية.

الفحص الإضافي للشعار استعمل قواعد جديدة بالمقدمة `nukhab_native_android_4efc45e822ae45f5` مع لاحقتي `_platform` و`_other`، ولم يعد استعمال بيانات قواعد التشغيل السابق.

تحقق guard من MySQL محلي ومن استعمال loader الاختبارات قبل استيراد الخادم. عُطلت تهيئة الإنتاج والمهام الخارجية وLiveKit ورسائل القبول. حُدد API على `127.0.0.1:55075` وMetro على `127.0.0.1:8095`، وربطا عبر `adb reverse` للمحاكي المملوك فقط. لم يُخمن عنوان إنتاجي من مفتاح الجهة.

كلمة المرور وُلدت لكل تشغيل ولم تسجل. لم يقرأ الفحص ملف SecureStore أو ينسخه، ولم يسجل التوكن أو هاشه. إثبات إلغاء الجلسة استعمل عدد صفوف قاعدة الاختبار. إعادة التوكن إلى الجهة الأخرى كانت داخل ذاكرة العملية وفي HTTP محلي فقط، ولم تحفظه الأدلة. بيانات الحسابات كلها مصطنعة.

## محاولات أداة الفحص والتنظيف

يحفظ `priorAttempts` ثلاث محاولات سابقة غير ناجحة وتشغيل المصادقة الناجح السابق: اختلاف نهاية السطر من `adb` في حارس AVD، ومحاولة توقفت قبل تأكيد شاشة الدخول دون تشخيص SDK حاسم، ثم حارس تقرير قارن `req.url` بعد تغييره داخل Express. أصلح الحارس الأخير لالتقاط المسار قبل دخول Router؛ استعادة الجلسة نفسها كانت تحصل على `200`. انتهى التشغيل الكامل والفحص الإضافي بكود خروج `0`، ولم تتطلب تصحيحات أداة الفحص تعديل التطبيق أو تعطيل أي اختبار.

أُوقفت عملية المحاكي النهائية `89696` وMetro `15172` وخادم API ومجمّعات MySQL الخاصة بالفحص. تحقق مستقل من غياب العمليتين وتحرير المنافذ `5584/5585/8095/55075`. أزيلت روابط reverse الخاصة، وألغيت جلسات قواعد fixture المتبقية. بقي تعريف AVD وقواعد البيانات المحلية للمراجعة؛ لا حذف لمجلدات محاكيات ولا `adb kill-server` أو اتصال إنتاجي.

وأُغلقت كذلك عمليتا الفحص الإضافي `81320` للمحاكي و`5108` لـMetro، مع تحرير منفذ API الجديد `57726` والمنافذ المشتركة المذكورة. تحقق غيابهما مستقلًا، وعاد وضع المحاكي إلى light قبل إغلاقه.

لإعادة الفحص من جذر المشروع باستخدام Node 24 وSDK المحلي:

```text
node --experimental-loader ./tests/fixtures/isolated-server-loader.mjs tests/nativeAuthEmulator.mjs
```

الفحص ينشئ قواعد fixture جديدة، ويعيد استعمال محاكي الاختبار المثبت فقط. يجب أن تكون منافذه خالية قبل التشغيل. الأدلة الحالية تخص تشغيلًا مكتملًا؛ لا تشمل الجهاز الفعلي أو iOS أو مزامنة التسميع أو ترحيل جلسات Capacitor القديمة.

إضافة `--smoke` للأمر تفحص النسخة الحالية في الوضعين وتنفذ دخول المدير وخروجه، مع إبقاء دليل التشغيل الكامل محفوظًا.
